# 放置动作对照：停稳、确认支撑、缓慢张爪

2026-10-29，在 seed 7、相同粗/精视觉、相同目标位置与控制增益下，对比原放置和新增 `settled` 策略。原策略继续作为默认基线，新增策略显式开启。

## 命令

```bash
# 原流程
./.venv/bin/python -m simulation.vision_pick_place --seed 7 --placement-strategy baseline --output runs/placement-baseline
# 新流程；加 --view 可观看机械臂及四个独立传感器窗口
./.venv/bin/python -m simulation.vision_pick_place --seed 7 --placement-strategy settled --output runs/placement-settled --view
```

## 改动

下放达到原来的阶段条件后，不立即张爪，新增 settle 阶段。保持当前通过 FK 测得的 TCP 位姿，避免张爪过程中继续追踪未达到的旧下放目标；不修改物体真值、不用器件位置真值生成新目标。最短等待 0.8 秒后，要求器件与台面接触的法向力 >0.02 N、TCP 线速度 <2 mm/s、角速度 <0.03 rad/s，连续满足至少 0.3 秒才允许张爪。超过 settle 开始后 3 秒仍未满足，报 `SEATING_TIMEOUT` 并停止，不跳过支撑检查。

确认后将夹爪张开时长从 1 秒延长为 3 秒，再撤离。其余抓取、抬升、转运、摩擦、运动增益和阶段容差保持不变。本轮是整套放置策略的对照，尚未单独归因到“停稳”“更换保持目标”或“慢张爪”中的某一项。

落座确认依赖 MuJoCo 的接触法向力作为虚拟传感信号，并非相机识别。真实硬件还需确认力/接触传感器、负载阈值与机械柔顺，不能直接把仿真门限作为实机设定。

最终 XY 误差下降约 43.5%，张爪 XY 位移下降约 72.6%。器件张开后的位移仍几乎为零。两次运行在抓取/运输部分一致，变化集中在放置与释放部分。

本地证据：`runs/placement-error-seed7` 与 `runs/placement-settled-seed7` 的 `result.json`、`error-breakdown.json`、阶段时序与诊断轨迹。新增流程的 `seating` 字段记录接触力与 TCP 速度，`seating.confirmed=true`；后续运行还单独保存确认瞬间的数值。已增加“静止但无支撑不许释放并超时”和“支撑须持续满足后才释放”的单元测试，合计 17 项通过。

这只是一个固定 seed 的对照，不代表多布局成功率或实机精度。当前仍有约 1 mm 初始夹持注册偏差与毫米级 TCP 阶段误差；下一轮可先将策略拆分做消融对照，或在这套诊断下单独收紧抓取/放置的终点误差，避免同时修改多类参数。
