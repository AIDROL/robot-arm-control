# 阶段进度：视觉抓放与相机监看（2026-10-28）

本阶段在已有 xArm7 MuJoCo 笛卡尔抓放上，增加了 FAT 几何对准、全局视觉定位、末端深度修正，以及可直接观看的本地相机播放器。当前全部为仿真，尚未操作真实硬件。

## 已实现

| 环节 | 当前能力 | 重要边界 |
| --- | --- | --- |
| FAT | 取用、五镜架侧面对准、撤离和放回的几何演示 | 无碰撞 mocap 工具代理，目标仍来自真值；未插孔或拧旋钮 |
| 全局相机 | 两台原生 3840 × 2160 RGB，真实 ArUco 渲染/检测、PnP 诊断及双机一致性检查 | 最终采用已知台面高度与直立物体先验，只估计位置与 yaw |
| 视觉抓放 | 一个指定镜架，图像估计驱动规划，真实接触夹持、转运、释放和稳定性验证 | 其他四个镜架作为障碍物；尚非多器件视觉装配 |
| 末端 RGB-D | 预抓取位拍摄 1280 × 720 RGB/深度，利用深度点拟合表面并修正三维抓取位置 | 保留全局朝向，理想 RGB-D 代理，未按 D435 实物参数约束 |
| 本地播放器 | 独立桌面窗口显示全局 A/B、末端 RGB 与伪彩深度，支持暂停画面和退出 | 640 × 360 实时预览，不参与定位；尚无历史录像时间轴 |
| 证据与失败处理 | 编号输出目录、观测/变换/轨迹/阶段/验收日志、原始帧及可选 GIF | 定位无效即停止，没有自主重试或真值回退 |

## 重现与验证

在原生 arm64 Python 3.11 虚拟环境中安装 `requirements.txt`。当前锁定 MuJoCo 3.16.0、Menagerie 包 2026.10.3、NumPy 2.4.6、SciPy 1.17.1、OpenCV contrib 5.0.0.93；模型首次使用需要下载资源。

```bash
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python -m unittest discover -s tests -v
./.venv/bin/python -m simulation.vision_pick_place --seed 7 --output runs/wrist-live-demo --view
```

`--view` 在 macOS 自动调用 MuJoCo 的 mjpython 启动器，支持项目路径含空格。默认另开原生 Robot Camera Player；添加 `--camera-display browser` 切换浏览器。低负载可用 `--camera-fps 2`。不加 `--view` 时只离屏运行。`--record-gif` 需要额外安装 ffmpeg。关闭 MuJoCo 窗口结束整个运行，播放器空格只暂停画面，Q/Esc 只关闭播放器。

负例与基线：

```bash
./.venv/bin/python -m simulation.vision_pick_place --seed 7 --hide-target-marker --output runs/hidden
./.venv/bin/python -m simulation.vision_pick_place --seed 7 --invalid-wrist-depth --output runs/invalid-depth
./.venv/bin/python -m simulation.vision_pick_place --seed 0 --coarse-offset-mm 5 -5 --output runs/offset
./.venv/bin/python -m simulation.vision_pick_place --seed 7 --coarse-only --output runs/coarse-only
./.venv/bin/python -m simulation.wrist_camera --output runs/depth-check
```

前两个负例预期失败退出：分别在启动前、在下降/闭合前停止。抓放输出目录重名自动编号；独立全局相机与深度平面测试仍要求新输出目录。

本机已通过 12 项单元测试，覆盖图像定位、消息校验、缺失标记/无效深度拒绝、无器件真值字段的规划、手眼坐标一致性及深度更新 Z。额外运行检查核对了四路画面随机械臂移动而变化，原生播放器窗口可见并连续更新 16 次，以及带监看的完整抓放成功。运行证据在本地 `runs/`，不入 Git。

| 已运行场景 | 粗位置误差 | 末端位置误差 | 最终放置 XY 误差 |
| --- | --- | --- | --- |
| seed 7，RGB-D 抓放 | 0.295 mm | 0.177 mm | 1.856 mm |
| seed 0，粗估计额外注入 X+5/Y−5 mm | 6.987 mm | 0.083 mm | 0.779 mm |

两次抓放通过夹持、抬升、转运、位置/姿态、松爪稳定及接触检查。此处是理想仿真记录，不是实际硬件精度或多 seed 成功率统计。现有 TCP 阶段容差为 5 mm，器件在夹持中也有相对漂移；定位误差与最终放置误差必须分开分析。

## 下一步与未验证事项

- 按 D435 实际工作模式更新视场、近距范围和 RGB/深度对齐；1280 × 720 深度模式最小测距约 280 mm，当前约 218 mm 的仿真观测不符合该模式。详见 [末端 RGB-D 参数边界](wrist-rgbd.md)。
- 与机械/电控负责人确认镜架、孔位、工具头、相机支架、TCP 和连接器/线缆空间；现有镜架 50 × 50 × 80 mm、FAT 36 × 16 × 90 mm 都是代理尺寸。
- 在实际安装后读取并核验相机内参、传感器间外参，执行手眼/TCP 标定；仿真指定的精确安装偏移不能替代标定。
- 分解运动控制、夹持漂移和放置接触误差，再扩展多器件视觉装配与 FAT 视觉对准。
- 后续再加入传感器噪声/畸变、真实插入/旋钮驱动和光学反馈，按真实驱动兼容范围确定 Ubuntu 部署环境。
