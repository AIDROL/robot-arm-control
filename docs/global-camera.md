# 双 4K 全局相机链路

此脚本单独验证静态场景的图像定位。[单镜架视觉抓放脚本](vision-pick-place.md) 复用同一相机/检测/择优接口，将视觉目标接入抓取控制。

## 运行

在项目根目录、可用的 macOS 桌面会话中运行：

```bash
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python -m simulation.global_camera --seed 7 --output runs/global-camera-demo
./.venv/bin/python -m unittest discover -s tests -v
```

输出目录必须尚不存在，以免覆盖已有证据。默认每台相机为原生 3840 × 2160；可用 `--width 1920 --height 1080` 调试，内参随分辨率重新计算。两台相机顺序渲染，属于同一静态仿真时刻；未模拟真实相机同步、曝光、畸变、噪声或实时视频采集。只有所有五个目标都有效、无双机冲突，且诊断中心误差均不超过 20 mm，进程才正常退出。

每台相机保存原始 RGB PNG、角点/原始 PnP 坐标轴叠图。`result.json` 保存内参、OpenCV 光学系到世界的外参、仿真时间、逐相机观测、原始 PnP、约束后的定位、两机差异、最终物体位姿与诊断误差。叠图坐标轴对应原始 PnP；最终采用已知平面约束后的估计。

## 临时几何约定

- 镜架继续使用 50 × 50 × 80 mm 长方体，FAT 继续使用 36 × 16 × 90 mm 主体。
- 字典 `DICT_4X4_50`；五个顶部标记 ID 为 0–4，侧面 ID 为 10–14。
- 顶部黑色标记外边长 24 mm、白底 32 mm；侧面黑色标记外边长 12 mm、白底 16 mm。边长不包含白色留白。
- 侧面标记位于 -X 面，横向居中，中心在镜架中心上方 24 mm。
- 两孔/旋钮目标整体移到标记下方，中点在镜架中心下方 10 mm，保留原来约 34 mm 的对角间距。此阶段仍为圆柱代理，未建真实孔腔。
- FAT 工具头尺寸、间距暂时保留；尺寸参数位于 `simulation/global_camera.py` 与原场景常量中，后续按子系统接口确认。
- 此布局仅在 `make_scene(vision=True, include_fat=True)` 的视觉场景启用；原 FAT 动作演示继续使用原布局。后续接入 FAT 视觉控制时必须统一相应标记到孔位的偏移，不能混用。

标记由 OpenCV 字典生成，以无碰撞的黑白网格几何进入真实渲染图像；不是截图粘贴或伪造检测结果。当前全局定位只消费顶部 ID，侧面标记留给 FAT 近距离相机。

## 定位与限制

1. 每台固定相机渲染 RGB，在全分辨率图像中检测 ArUco 并细化角点。
2. 用已知标记边长和内参做 IPPE PnP，剔除朝向/深度不合理的解，记录重投影误差。
3. 小标记单目 PnP 深度与倾角可能波动。当前明确使用“已知尺寸镜架直立在固定台面上”的先验：将角点射线与已知顶部平面相交，得到位置及 yaw。该方法不估计任意 roll/pitch，不适用于举起、倾倒或未知高度的器件。
4. 两机都有效时检查 20 mm 位置一致性与 15° 姿态一致性，然后按原始 PnP 重投影误差择优；仅一路有效时使用该路。两路无效不提供真值回退。
5. 标记到器件中心的偏移来自已知几何；`locate` 仅接受 RGB、内参、固定相机外参和已知平面高度，不接收 MuJoCo 对象。
6. 全部图像估计完成后，诊断评估器才读取物体真值计算误差。物体高度由配置约束，因此高度误差不构成独立的深度测量验证。

## 2026-10-28 本机验证

Mac arm64，MuJoCo 3.16.0，OpenCV contrib 5.0.0.93，NumPy 2.4.6。

| seed | A 检出顶部 ID | B 检出顶部 ID | 最终有效物体数 | 最大中心误差 |
| --- | --- | --- | --- | --- |
| 7 | 0,1,2,3,4 | 0,2,3,4 | 5/5 | 0.295 mm |
| 0 | 0,2,3 | 0,1,2,3,4 | 5/5 | 0.145 mm |

对应证据目录：`runs/global-4k-seed7-plane`、`runs/global-4k-seed0-plane`。未约束的原始 PnP 曾出现厘米级误差与两机冲突，因此不将其作为当前最终定位。单帧渲染约 112–145 ms，检测约 23–47 ms，不含 PNG 保存；这是两次运行的单帧计时，不是实时帧率基准。

三个图像单元测试通过：空白图无定位回退、独立指定内参与高度的居中标记坐标核对、相机后方的无效平面被拒绝。上述两次仿真不等同于 10-seed 端到端抓取验收，也不代表真实相机毫米级精度。

## Ubuntu 迁移节点

本阶段继续使用 Mac；4K 分辨率本身不要求 Ubuntu。接入真实机械臂、RGB-D 相机和 FAT 电机前，按各厂商 SDK 与选定 ROS 版本的共同支持范围选 Ubuntu 版本，并将部署环境固定。若提前需要 NVIDIA GPU、大批量无窗口渲染或服务器运行，可先把仿真执行端移到 Linux，保留 Mac 开发端。

MuJoCo 的 Linux 渲染支持 EGL 硬件离屏、OSMesa 软件离屏及 GLX 窗口。参考：[官方渲染说明](https://mujoco.readthedocs.io/en/latest/programming/rendering.html)。若选 ROS 2 Jazzy，对应 Ubuntu 24.04；其他发行版应查各自支持矩阵：[ROS 目标平台](https://reps.openrobotics.org/rep-2000/)。
